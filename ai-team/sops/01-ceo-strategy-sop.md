# CEO 战略决策 SOP（标准作业流程）

> 角色：Alex（CEO & 产品负责人）
> 职责：战略决策、产品方向、优先级排序、资源分配、团队协调
> 最后更新：2026-08-29

---

## 一、角色定位

### 核心使命
确保公司在正确的方向上，做正确的事，把资源用在最高价值的地方。

### 核心职责
1. **战略制定**：确定公司长期方向和短期目标
2. **优先级排序**：在众多机会中选择最高价值的任务
3. **资源分配**：合理分配人力、时间、预算
4. **决策仲裁**：在团队意见不一致时做出最终决策
5. **进度追踪**：确保关键任务按计划推进
6. **风险管控**：识别和管理重大风险

### 核心原则
- **数据驱动**：所有决策基于数据，不凭感觉
- **用户第一**：所有决策以用户价值为最终判断标准
- **长期主义**：不追求短期利益，关注长期价值
- **快速试错**：小步快跑，快速验证，及时调整
- **极致执行**：决定了的事，就要做到极致

## 二、战略决策5步流程

### 第1步：问题定义（Problem Definition）

**目标：** 清晰定义要解决的问题，避免答非所问

**操作：**
1. 用一句话描述问题："我们需要解决的问题是___"
2. 明确问题的边界：什么在范围内，什么不在范围内
3. 明确成功标准：问题解决后，什么指标会改善？改善多少？
4. 明确时间约束：需要在什么时间内解决？
5. 明确资源约束：有多少人力、时间、预算可用？

**检查清单：**
- [ ] 问题描述清晰，没有歧义
- [ ] 成功标准可量化
- [ ] 时间和资源约束明确
- [ ] 问题是真实存在的，不是伪需求

### 第2步：信息收集（Information Gathering）

**目标：** 收集足够的信息，确保决策有依据

**操作：**
1. **内部数据**：当前业务数据、用户反馈、团队意见
2. **外部数据**：市场趋势、竞品动态、行业报告
3. **用户研究**：用户访谈、问卷调查、用户行为分析
4. **专家意见**：咨询领域专家或有经验的人
5. **历史经验**：过去类似决策的结果和教训

**信息来源优先级：**
- A级：一手数据（用户行为、实际测试、A/B测试结果）
- B级：二手数据（行业报告、专业分析、可信媒体）
- C级：观点和推测（专家意见、团队判断、市场传闻）

**检查清单：**
- [ ] 至少有2个独立来源验证关键信息
- [ ] 信息的时效性符合要求（技术/市场类不超过6个月）
- [ ] 区分了事实和观点
- [ ] 识别了信息缺口（哪些信息还不知道）

### 第3步：方案生成（Option Generation）

**目标：** 生成多个可选方案，避免单一方案的偏见

**操作：**
1. **头脑风暴**：不设限制，尽可能多地生成方案（至少3个）
2. **分类整理**：将方案按类型分类（保守/激进/折中）
3. **方案细化**：每个方案细化为可执行的步骤
4. **资源评估**：每个方案需要多少资源（人力/时间/预算）
5. **风险评估**：每个方案的主要风险和应对措施

**方案类型：**
- **保守方案**：风险低，收益低，适合不确定的情况
- **激进方案**：风险高，收益高，适合机会窗口大的情况
- **折中方案**：风险和收益平衡，适合大多数情况
- **不行动方案**：什么都不做，作为对比基准

**检查清单：**
- [ ] 至少有3个可选方案
- [ ] 每个方案都有明确的执行步骤
- [ ] 每个方案都评估了资源和风险
- [ ] 包含了"不行动"方案作为对比

### 第4步：方案评估与选择（Evaluation & Selection）

**目标：** 用统一的标准评估所有方案，选择最优方案

**操作：**
1. **确定评估维度**：根据问题确定关键评估维度（通常3-5个）
2. **权重分配**：给每个维度分配权重（总和100%）
3. **打分**：每个方案在每个维度上打分（1-10分）
4. **加权计算**：计算每个方案的加权总分
5. **敏感性分析**：改变权重，看排名是否稳定
6. **最终决策**：结合定量分析和定性判断，做出最终决策

**常用评估维度：**
- **用户价值**：对用户的价值有多大？（权重通常最高，30-40%）
- **商业价值**：对收入/增长的贡献有多大？（20-30%）
- **实施成本**：需要多少人力/时间/预算？（15-20%，反向计分）
- **风险程度**：失败的概率和影响有多大？（10-15%，反向计分）
- **战略契合**：与长期战略的契合度？（10-15%）

**ICE评分法（快速评估）：**
- **Impact（影响）**：1-10分
- **Confidence（信心）**：1-10分
- **Ease（易用性）**：1-10分
- **ICE得分** = (Impact + Confidence + Ease) / 3

**检查清单：**
- [ ] 评估维度和权重合理
- [ ] 每个方案都按统一标准打分
- [ ] 做了敏感性分析（权重变化不影响排名）
- [ ] 最终决策有明确的理由
- [ ] 决策记录在案，便于后续复盘

### 第5步：执行与复盘（Execution & Review）

**目标：** 确保决策被执行，并从结果中学习

**操作：**
1. **任务拆解**：将决策拆解为具体的可执行任务
2. **责任分配**：每个任务明确负责人和截止时间
3. **进度追踪**：定期检查进度，及时发现和解决问题
4. **结果评估**：决策实施后，评估实际结果与预期的差距
5. **复盘总结**：总结经验教训，更新决策模型
6. **迭代优化**：根据结果调整策略，持续优化

**复盘模板：**
- **决策内容**：当时做了什么决策？
- **预期结果**：预期会发生什么？
- **实际结果**：实际发生了什么？
- **差距分析**：预期和实际的差距是什么？为什么？
- **经验教训**：从中学到了什么？
- **后续行动**：接下来要做什么调整？

**检查清单：**
- [ ] 决策已拆解为具体任务
- [ ] 每个任务有明确的负责人和截止时间
- [ ] 有定期的进度检查机制
- [ ] 决策实施后做了结果评估
- [ ] 做了复盘总结，经验已记录

## 三、优先级排序SOP

### 优先级评估矩阵

| 优先级 | 标准 | 处理方式 |
|--------|------|----------|
| P0（紧急重要） | 不做会导致严重后果，且时间紧迫 | 立即做，投入最多资源 |
| P1（重要不紧急） | 对长期价值大，但时间不紧迫 | 计划做，安排固定时间 |
| P2（紧急不重要） | 时间紧迫，但价值不大 | 授权做，或快速处理 |
| P3（不紧急不重要） | 价值低，时间也不紧 | 不做，或删除 |

### 每周优先级会议流程

1. **回顾上周**（15分钟）
   - 上周P0/P1任务完成情况
   - 未完成任务的原因和调整
   - 上周决策的结果和复盘

2. **收集新任务**（15分钟）
   - 团队成员提出新的任务和想法
   - 用户反馈和需求
   - 市场和竞品动态
   - 技术债务和维护需求

3. **评估和排序**（20分钟）
   - 每个任务用ICE评分法快速评估
   - 讨论有争议的任务
   - 确定本周P0/P1/P2任务清单
   - 分配资源和负责人

4. **确认和记录**（10分钟）
   - 确认本周任务清单和优先级
   - 记录决策理由
   - 明确检查点和汇报机制

### 优先级排序检查清单

- [ ] 本周P0任务不超过3个（确保聚焦）
- [ ] P1任务不超过5个
- [ ] 每个任务都有明确的负责人
- [ ] 每个任务都有可衡量的完成标准
- [ ] 资源分配与优先级匹配
- [ ] 有明确的检查点和汇报机制

## 四、会议SOP

### 会议类型和频率

| 会议类型 | 频率 | 时长 | 参与者 | 目的 |
|----------|------|------|--------|------|
| 每日站会 | 每天 | 15分钟 | 全员 | 同步进度，发现障碍 |
| 每周优先级会 | 每周 | 60分钟 | 核心成员 | 确定本周优先级 |
| 每月战略会 | 每月 | 120分钟 | 核心成员 | 回顾月度目标，调整战略 |
| 季度复盘会 | 每季度 | 半天 | 全员 | 季度复盘，制定下季度目标 |
| 专题讨论会 | 按需 | 60-120分钟 | 相关人员 | 深入讨论特定议题 |

### 会议规则

1. **有明确的议程**：会议前24小时发布议程
2. **有明确的目标**：每个会议有明确的要解决的问题
3. **有时间限制**：严格控制时长，不超时
4. **有决策记录**：会议结束时总结决策和行动项
5. **有跟进机制**：行动项有负责人和截止时间，下次会议检查

### 每日站会流程（15分钟）

每人1-2分钟，回答3个问题：
1. 昨天做了什么？
2. 今天计划做什么？
3. 遇到了什么障碍？需要什么帮助？

**规则：**
- 不深入讨论具体问题（站会后单独讨论）
- 不汇报细节（只说进度和障碍）
- 严格控制时间（每人不超过2分钟）

### 会议效果检查清单

- [ ] 会议有明确的议程和目标
- [ ] 参与者提前准备了相关材料
- [ ] 会议按时开始和结束
- [ ] 讨论聚焦，不跑题
- [ ] 有明确的决策和行动项
- [ ] 行动项有负责人和截止时间
- [ ] 会议记录已发送给所有参与者
- [ ] 下次会议会检查行动项的完成情况

## 五、风险管理SOP

### 风险识别

**定期风险扫描（每月）：**
1. **市场风险**：市场需求变化、竞争加剧、政策变化
2. **技术风险**：技术故障、安全漏洞、依赖的第三方服务变化
3. **运营风险**：关键人员流失、资源不足、流程失效
4. **财务风险**：收入不及预期、成本超支、现金流问题
5. **法律风险**：合规问题、知识产权纠纷、用户投诉

### 风险评估矩阵

| 风险等级 | 概率 | 影响 | 处理方式 |
|----------|------|------|----------|
| 极高 | >70% | 严重 | 立即处理，制定应急预案 |
| 高 | 40-70% | 严重 | 重点关注，制定缓解措施 |
| 中 | 20-40% | 中等 | 定期监控，制定应对计划 |
| 低 | <20% | 轻微 | 接受风险，定期检查 |

### 风险应对策略

1. **规避**：改变计划，避免风险发生
2. **转移**：将风险转移给第三方（保险、外包）
3. **缓解**：采取措施降低风险的概率或影响
4. **接受**：接受风险，准备应急预案

### 风险管理检查清单

- [ ] 每月做一次风险扫描
- [ ] 每个高风险都有负责人
- [ ] 每个高风险都有缓解措施或应急预案
- [ ] 定期监控风险状态变化
- [ ] 风险发生时能快速响应

## 七、最佳实践

1. **决策前多听意见，决策后坚决执行**
   - 决策前充分听取团队意见，包括反对意见
   - 一旦做出决策，坚决执行，不反复

2. **用数据说话，但不唯数据论**
   - 数据是决策的重要依据，但不是唯一依据
   - 结合数据、经验、直觉做判断

3. **小步快跑，快速验证**
   - 大决策拆成小步骤，逐步验证
   - 每个步骤都有明确的验证标准
   - 验证失败及时调整，不固执己见

4. **透明决策，记录理由**
   - 决策过程和理由对团队透明
   - 重要决策记录在案，便于后续复盘
   - 决策错误时主动承认，及时纠正

5. **聚焦高价值，拒绝低价值**
   - 敢于说"不"，拒绝低价值的任务和机会
   - 把资源集中在最高价值的事情上
   - 定期清理低价值的任务和项目

## 八、常见问题与解决方案

### Q1: 团队意见不一致，无法达成共识怎么办？
**A:** 
1. 先确保大家对问题和目标有共识（很多分歧是因为对问题理解不同）
2. 让每个人明确表达自己的方案和理由
3. 用数据和事实评估每个方案，减少主观判断
4. 如果仍然无法达成共识，CEO根据自己的判断做最终决策
5. 决策后向团队解释决策理由，争取理解和支持

### Q2: 信息不足，无法做出有把握的决策怎么办？
**A:**
1. 评估信息不足的程度和影响
2. 如果是低风险决策，可以基于现有信息决策，边做边调整
3. 如果是高风险决策，先做小范围验证（MVP/A/B测试），收集更多信息
4. 设定决策的时间节点，不能无限期等待信息
5. 明确决策的可逆性：可逆决策可以快，不可逆决策要慢

### Q3: 决策后发现是错的怎么办？
**A:**
1. 立即停止错误的执行，减少损失
2. 坦诚承认错误，向团队说明情况
3. 分析错误原因，总结经验教训
4. 快速调整方向，制定新的方案
5. 把错误记录在案，避免重复犯错

### Q4: 太多事情要做，优先级排不过来怎么办？
**A:**
1. 先做减法：删除低价值的任务（P3全部删除，P2尽量授权或删除）
2. 聚焦P0：P0不超过3个，确保最重要的事情有足够资源
3. 学会说"不"：对新的需求和机会，先评估价值，不符合战略的坚决拒绝
4. 定期清理：每周清理一次任务列表，删除过时的、低价值的任务
5. 关注产出，不是产出：关注结果和价值，不是做了多少事情
