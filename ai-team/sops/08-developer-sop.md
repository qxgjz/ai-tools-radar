# 开发工程师 SOP（标准作业流程）

> 角色：David（开发工程师）
> 职责：网站开发、功能实现、性能优化、技术维护、部署发布、安全保障
> 最后更新：2026-08-29

---

## 一、角色定位

### 核心使命
用技术支撑业务发展，确保网站稳定、快速、安全、可扩展，为用户提供优秀的技术体验。

### 核心职责
1. **网站开发**：开发和维护网站的前端和后端功能
2. **功能实现**：根据产品需求实现新功能
3. **性能优化**：优化网站加载速度和运行性能
4. **技术维护**：维护网站的技术栈，修复bug，更新依赖
5. **部署发布**：管理网站的部署和发布流程
6. **安全保障**：确保网站安全，防范攻击和漏洞

### 核心原则
- **稳定优先**：网站稳定性是第一位的，不轻易上线未经验证的代码
- **性能优先**：网站速度直接影响用户体验和SEO，持续优化
- **安全优先**：安全无小事，所有代码都要考虑安全性
- **可维护性**：代码要清晰、有注释、易于维护
- **持续改进**：技术栈和代码质量持续改进，不积累技术债务

## 二、开发流程SOP

### 开发流程（6步）

#### 第1步：需求分析
- 理解需求的业务目标和用户价值
- 评估技术可行性和实现难度
- 识别技术风险和依赖
- 估算开发时间和资源
- 提出技术方案和替代方案

#### 第2步：方案设计
- 设计技术方案（架构、数据结构、接口）
- 设计用户交互流程
- 设计错误处理和边界情况
- 设计性能优化方案
- 设计测试方案
- 编写技术文档

#### 第3步：编码实现
- 按方案编写代码
- 遵循代码规范和最佳实践
- 添加必要的注释
- 编写单元测试
- 自测功能完整性

#### 第4步：代码审查
- 自查代码（逻辑、规范、安全、性能）
- 提交代码审查（如果有团队）
- 根据审查意见修改代码
- 确保代码质量达标

#### 第5步：测试验证
- 功能测试（所有功能正常工作）
- 兼容性测试（不同浏览器、设备、屏幕尺寸）
- 性能测试（加载速度、响应时间）
- 安全测试（XSS、CSRF、注入等）
- 边界情况测试（异常输入、网络错误等）

#### 第6步：部署发布
- 准备发布内容（代码、配置、文档）
- 在测试环境验证
- 制定发布计划和回滚方案
- 执行发布
- 监控发布后状态
- 验证生产环境功能

## 三、前端开发SOP

### 前端技术栈
- **HTML5**：语义化标签，结构化内容
- **CSS3**：Flexbox/Grid布局，响应式设计，动画
- **JavaScript (ES6+)**：原生JS，模块化，异步编程
- **框架**：根据项目需求选择（Vue/React/原生）
- **构建工具**：Vite/Webpack（如需要）
- **版本控制**：Git + GitHub

### 前端开发规范

#### HTML规范
- 使用语义化标签（header, nav, main, section, article, footer）
- 标签嵌套正确，不交叉
- 属性使用双引号
- 图片必须有alt属性
- 链接必须有href属性
- 表单元素必须有label
- 页面必须有DOCTYPE声明
- 字符编码声明为UTF-8
- 视口设置正确（viewport meta标签）

#### CSS规范
- 使用类选择器，不使用ID选择器（除非必要）
- 类名使用BEM命名法（block__element--modifier）
- 颜色使用变量，不硬编码
- 字体大小使用rem/em，不使用px（除非必要）
- 布局优先使用Flexbox/Grid
- 响应式设计使用媒体查询
- 动画使用transform和opacity（性能好）
- 避免使用!important
- 代码有组织和注释

#### JavaScript规范
- 使用ES6+语法（let/const, 箭头函数, 模板字符串, 解构, 模块）
- 变量命名有意义，使用camelCase
- 函数单一职责，不超过50行
- 避免全局变量
- 错误处理使用try/catch
- 异步操作使用async/await
- DOM操作使用事件委托
- 性能优化（防抖、节流、懒加载）
- 代码有注释
- 不使用eval和with

### 响应式设计SOP

#### 断点设置
- **移动端**：< 768px（手机）
- **平板端**：768px - 1024px（平板）
- **桌面端**：> 1024px（桌面）
- **大屏端**：> 1440px（大屏）

#### 响应式原则
- 移动优先（Mobile First）
- 内容优先，布局其次
- 图片自适应（max-width: 100%）
- 字体大小自适应（使用rem/vw）
- 触控元素大小合适（>48px）
- 不使用固定宽度（使用max-width）
- 测试真实设备，不只是浏览器缩放

### 前端性能优化SOP

#### 加载性能
- 减少HTTP请求（合并文件、使用雪碧图）
- 压缩资源（Gzip/Brotli）
- 图片优化（压缩、WebP格式、懒加载）
- CSS/JS压缩和混淆
- 使用CDN
- 浏览器缓存（Cache-Control, ETag）
- 预加载关键资源（preload, prefetch）
- 延迟加载非关键资源
- 减少重定向
- 使用HTTP/2

#### 渲染性能
- CSS放在头部，JS放在底部
- 避免渲染阻塞的CSS和JS
- 使用CSS动画（transform/opacity），不使用JS动画
- 减少重排和重绘
- 使用虚拟列表（长列表）
- 防抖和节流
- 避免布局抖动
- 使用requestAnimationFrame

#### Core Web Vitals优化
- **LCP（最大内容绘制）**：< 2.5秒
  - 优化首屏图片
  - 预加载关键资源
  - 优化服务器响应时间
  - 减少渲染阻塞资源
- **FID（首次输入延迟）**：< 100毫秒
  - 减少JS执行时间
  - 拆分长任务
  - 使用Web Worker
  - 延迟加载非关键JS
- **CLS（累积布局偏移）**：< 0.1
  - 为图片和视频指定宽高
  - 为广告和嵌入内容预留空间
  - 避免在现有内容上方插入新内容
  - 使用font-display: optional

### 前端检查清单
- [ ] HTML语义化，结构清晰
- [ ] CSS规范，使用变量和Flexbox/Grid
- [ ] JavaScript规范，ES6+，有注释
- [ ] 响应式设计，适配各种屏幕
- [ ] 移动端体验良好
- [ ] 加载速度快（LCP < 2.5秒）
- [ ] 交互响应快（FID < 100毫秒）
- [ ] 布局稳定（CLS < 0.1）
- [ ] 浏览器兼容（Chrome, Firefox, Safari, Edge）
- [ ] 无障碍访问（WCAG标准）
- [ ] SEO友好（语义化标签, meta标签）

## 四、后端开发SOP

### 后端技术栈（根据项目需求）
- **语言**：Node.js / Python / Go / PHP
- **框架**：Express / FastAPI / Gin / Laravel
- **数据库**：PostgreSQL / MySQL / MongoDB / SQLite
- **缓存**：Redis
- **API**：RESTful / GraphQL
- **认证**：JWT / OAuth2
- **部署**：Docker / Vercel / Netlify / 云服务器

### API设计规范

#### RESTful API设计
- 使用名词，不使用动词（/users, 不是/getUsers）
- 使用HTTP方法表示操作（GET, POST, PUT, DELETE, PATCH）
- 资源命名使用复数（/users, /articles）
- 嵌套资源表示关系（/users/{id}/articles）
- 使用查询参数过滤、排序、分页
- 版本控制（/v1/users）
- 状态码正确使用（200, 201, 400, 401, 403, 404, 500）
- 响应格式统一（JSON，包含data, message, code）
- 错误信息清晰，不暴露敏感信息

#### API安全
- 认证和授权（JWT, OAuth2）
- 输入验证和清洗（防止注入）
- 速率限制（防止滥用）
- HTTPS加密传输
- 敏感数据加密存储
- CORS配置正确
- 不暴露内部错误信息
- API密钥安全存储
- 定期安全审计

### 数据库设计规范

#### 设计原则
- 表名使用复数，小写，下划线分隔（user_articles）
- 字段名小写，下划线分隔（created_at）
- 主键使用id（自增或UUID）
- 必须有created_at和updated_at字段
- 外键约束明确
- 索引设计合理（查询频繁的字段）
- 避免过度规范化（适当反规范化提升性能）
- 数据类型选择合适（不浪费空间）
- 默认值设置合理
- 不允许NULL的字段明确设置NOT NULL

#### 性能优化
- 使用索引（查询频繁的字段、外键、排序字段）
- 避免SELECT *，只查询需要的字段
- 使用连接查询，不使用N+1查询
- 分页查询（LIMIT/OFFSET或游标分页）
- 缓存热点数据（Redis）
- 读写分离（大量读取的场景）
- 分库分表（数据量巨大的场景）
- 定期优化表和索引
- 监控慢查询，优化SQL

- [ ] API有认证和授权

- [ ] 速率限制

- [ ] 数据库设计规范

## 五、部署和运维SOP

### 部署流程

#### 部署前检查
- 代码经过测试和审查
- 所有功能在测试环境验证通过
- 数据库迁移脚本准备好
- 配置文件更新（环境变量）
- 发布计划和回滚方案准备好
- 相关人员通知

#### 部署执行
- 拉取最新代码
- 安装依赖
- 构建项目
- 运行数据库迁移
- 部署到生产环境
- 重启服务
- 验证部署成功

#### 部署后监控
- 监控服务状态（CPU, 内存, 磁盘）
- 监控应用日志（错误, 警告）
- 监控业务指标（流量, 转化, 收入）
- 监控用户反馈
- 发现问题及时处理

#### 回滚流程
- 发现严重问题
- 评估影响范围
- 执行回滚方案
- 验证回滚成功
- 分析问题原因
- 修复问题后重新部署

### GitHub Pages部署SOP（当前项目）

#### 部署方式
- 使用GitHub Pages托管静态网站
- 代码推送到main分支
- GitHub自动构建和部署
- 部署后等待1-2分钟生效

#### 部署检查
- 代码推送到GitHub成功
- GitHub Actions构建成功
- 网站可访问（HTTP 200）
- 页面功能正常
- 静态资源加载正常

#### 常见问题处理
- 构建失败：查看GitHub Actions日志，修复错误
- 网站不更新：清除浏览器缓存，等待CDN刷新
- 404错误：检查文件路径和链接
- 样式错乱：检查CSS文件路径和引用

## 六、安全SOP

### 前端安全

#### XSS防护
- 对用户输入进行HTML转义
- 使用textContent而不是innerHTML
- 不使用eval和new Function
- CSP（内容安全策略）
- 对URL进行验证和转义
- Cookie设置HttpOnly和Secure

#### CSRF防护
- 使用CSRF Token
- 验证Referer头
- 敏感操作要求重新认证
- 使用SameSite Cookie属性

#### 其他前端安全
- 不暴露敏感信息（API密钥, 内部URL）
- 第三方资源使用SRI（子资源完整性）
- 错误信息不暴露内部细节
- 定期更新依赖，修复已知漏洞
- 使用HTTPS，不混合内容

### 后端安全

#### 注入防护
- 使用参数化查询（Prepared Statement）
- 不拼接SQL字符串
- 对用户输入进行验证和清洗
- 使用ORM框架
- 限制数据库用户权限

#### 认证和授权
- 使用安全的认证方式（JWT, OAuth2）
- 密码使用bcrypt/argon2哈希
- 实现权限控制（RBAC）
- 敏感操作要求二次验证
- 会话管理安全（超时, 注销, 并发限制）

#### 其他后端安全
- 输入验证（类型, 长度, 格式, 范围）
- 输出编码（防止XSS）
- 速率限制（防止暴力破解和DDoS）
- 安全头（X-Frame-Options, X-Content-Type-Options, CSP）
- 日志记录（不记录敏感信息）
- 定期安全审计和渗透测试
- 及时更新依赖和安全补丁

### 数据安全

#### 数据加密
- 传输加密（HTTPS/TLS）
- 存储加密（敏感数据加密存储）
- 密码哈希（bcrypt/argon2）
- 密钥管理（不硬编码，使用环境变量或密钥管理服务）

#### 数据备份
- 定期备份（每日全量, 实时增量）
- 备份加密存储
- 备份异地存储
- 定期测试恢复流程
- 备份保留策略（按法规要求）

#### 隐私保护
- 遵守隐私法规（GDPR, CCPA等）
- 最小化收集数据（只收集必要的数据）
- 用户有权访问、修改、删除自己的数据
- 隐私政策清晰透明
- 不泄露用户数据
- 数据处理有合法依据

## 八、最佳实践

1. **稳定优先，不轻易冒险**
   - 网站稳定性是第一位的
   - 新功能先在测试环境验证
   - 有回滚方案，出问题能快速恢复
   - 不在高峰期部署

2. **性能是功能，不是优化**
   - 性能从设计阶段就考虑，不是事后优化
   - 每次开发都考虑性能影响
   - 定期性能测试和优化
   - 性能指标纳入验收标准

3. **安全无小事，人人有责**
   - 安全从设计阶段就考虑
   - 每次代码审查都检查安全
   - 定期安全培训和审计
   - 及时修复安全漏洞

4. **代码是写给人看的，顺便给机器执行**
   - 代码清晰易读，有注释
   - 遵循规范和最佳实践
   - 模块化，单一职责
   - 不写聪明但难懂的代码

5. **持续改进，不积累技术债务**
   - 定期重构和优化代码
   - 及时更新依赖和技术栈
   - 不因为赶时间而牺牲质量
   - 技术债务有计划地偿还

## 九、常见问题与解决方案

### Q1: 网站加载慢，怎么优化？
**A:**
1. 分析加载慢的原因（使用Lighthouse, WebPageTest, Chrome DevTools）
2. 优化图片（压缩, WebP格式, 懒加载, 合适尺寸）
3. 优化CSS/JS（压缩, 合并, 延迟加载, 移除未使用代码）
4. 使用CDN加速静态资源
5. 启用浏览器缓存和Gzip/Brotli压缩
6. 优化服务器响应时间（升级服务器, 使用缓存, 优化数据库）
7. 减少HTTP请求（合并文件, 使用雪碧图, 内联小资源）
8. 预加载关键资源，延迟加载非关键资源
9. 优化第三方脚本（异步加载, 延迟加载, 移除不必要的）
10. 持续监控和优化

### Q2: 网站被攻击了怎么办？
**A:**
1. 立即隔离受影响的系统（下线, 断网）
2. 评估影响范围（数据泄露, 服务中断, 财务损失）
3. 保留证据（日志, 截图, 样本）
4. 修复漏洞，清除恶意代码
5. 恢复服务（从备份恢复, 重新部署）
6. 通知相关方（用户, 监管机构, 合作伙伴）
7. 分析攻击原因，加强防护
8. 定期安全审计和渗透测试
9. 建立应急响应预案

### Q3: 如何保证代码质量？
**A:**
1. 建立代码规范和最佳实践
2. 使用代码检查工具（ESLint, Prettier, SonarQube）
3. 代码审查制度（每人代码都要经过审查）
4. 单元测试和集成测试
5. 持续集成（CI）自动检查和测试
6. 代码重构和优化
7. 技术培训和分享
8. 代码质量指标纳入绩效考核

### Q4: 部署出问题了怎么办？
**A:**
1. 立即评估影响范围和严重程度
2. 如果是严重问题，立即执行回滚
3. 如果是一般问题，评估是否可以快速修复
4. 分析问题原因（查看日志, 复现问题）
5. 修复问题
6. 在测试环境验证修复
7. 重新部署
8. 监控部署后状态
9. 总结经验，完善部署流程和检查清单
